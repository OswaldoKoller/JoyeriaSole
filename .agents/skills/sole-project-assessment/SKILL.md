# Diagnóstico del proyecto

Leer [plan de verificación](../../../docs/engineering/VERIFICATION-PLAN.md), [AGENTS.md](../../../AGENTS.md) y pendientes de negocio referidos allí.

Contrastar cada afirmación histórica con código o una ejecución reproducible. Clasificar verificado, fallo, bloqueado y no ejecutado. Revisar primero scripts y aislamiento de datos; después ejecutar las etapas autorizadas. No ejecutar limpieza sobre datos de desarrollo.

Entregar matriz requisito → código → prueba → estado, riesgos con impacto/probabilidad y tareas con criterio de aceptación y dependencias. Usar la [plantilla](../../../docs/engineering/TASK-TEMPLATE.md). El número de tests no prueba cobertura de reglas. No aprobar Fase 1 ni reglas del cliente por inferencia.
